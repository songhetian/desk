# PRD — 客服违禁词桌面监控工具

> 本需求文档由 grill 对齐结论（CONTEXT.md + ADR 0001/0002/0003）合成。
> 领域术语以 CONTEXT.md 为准。

## Problem Statement（问题陈述）

客服人员在与客户在线沟通时，可能在**指定客服系统 / 聊天工具**中输入违规、敏感或违反公司合规要求的词汇。当前缺乏一种**本地、离线、可局域网统一部署**的手段，在输入发生的当下自动发现这些违禁词并即时提醒客服，同时把每次触发留痕以便事后复核。事后人工抽检无法覆盖实时沟通，且跨多台客服终端难以统一管控词库。

## Solution（解决方案）

一套 Windows 桌面工具，由两部分组成，**无运行时服务器**：

- **监控客户端（Client）**：部署在每台客服终端，系统托盘常驻、后台静默运行（主窗口可一键最小化到托盘，关闭按钮默认最小化到托盘而非退出，需在托盘右键菜单选择退出）。通过 **UI Automation** 监听**指定进程（按 EXE 名）**输入框的文本变化，读取已成型中文文本；用 **Aho-Corasick 多模自动机**与**本地词库文件**（`wordlib.json`）匹配；命中即触发可独立开关的**弹窗 / 声音 / 自有界面高亮**告警，并写入 **SQLite 审计日志**（时间、目标软件、触发内容、处理结果）。非目标软件的输入完全不受影响。客户端用 `FileSystemWatcher` 监听本地词库文件变更并热重载，离线天然可用。客户端另提供**可拖拽的悬浮球状态指示灯**：平时蓝色呼吸表示监控中，命中违禁词时变红脉冲，词库离线/引擎异常时变灰黄，作为托盘之外的实时健康灯（详见实现决策）。
- **词库编辑工具（Admin Tool，非服务）**：管理员桌面上运行的轻量程序（非后台服务），提供违禁词库的**增删改查与导入导出**，导出权威 **`wordlib.json`**。管理员通过任意手段（可访问的共享目录、U 盘、邮件、组策略/GPO）把该文件分发到各客户端；客户端读取本地副本即可。

两端均基于 **.NET Framework 4.8 + WinForms**，无需联网、无需额外运行时安装、无需独立服务器进程。

## User Stories（用户故事）

### 管理员 / 词库编辑工具
1. 作为管理员，我希望在管理端新增一条违禁词，以便把新发现的敏感词纳入管控。
2. 作为管理员，我希望编辑已有违禁词的内容/分类/级别，以便修正误录或调整口径。
3. 作为管理员，我希望删除某条违禁词，以便移除已不再违规的词。
4. 作为管理员，我希望批量导入违禁词（CSV/JSON），以便一次性初始化或定期更新大词库。
5. 作为管理员，我希望导出当前词库，以便备份或在其他环境复用。
6. 作为管理员，我希望为每条违禁词设置「启用/停用」，以便临时关闭某类词而不删除。
7. 作为管理员，我希望在编辑工具中导出 `wordlib.json`，以便分发到各客户端本地。
8. 作为管理员，我希望查看词库最后更新时间，以便确认分发是否已生效。
9. 作为管理员，我希望配置「被监控的目标软件列表」（按进程 EXE 名），以便限定监控范围。
10. 作为管理员，我希望在编辑工具中查看词库统计与导出状态，以便确认分发内容。（可选）

### 客服人员 / 客户端
11. 作为客服人员，我希望客户端在开机后后台静默运行，以便不打扰我日常接待。
12. 作为客服人员，我希望只有指定的客服/聊天软件被监控，以便我在其他软件里输入完全自由。
13. 作为客服人员，当我在目标软件输入了违禁词时，我希望立刻收到弹窗提醒，以便及时修改。
14. 作为客服人员，当我在嘈杂环境中，我希望有声音提醒，以便不漏看弹窗。
15. 作为客服人员，我希望弹窗里把触发的违禁词标红高亮，以便我快速定位要改的字。
16. 作为客服人员，我希望能分别关闭弹窗/声音/高亮，以便按需选择提醒方式。
17. 作为客服人员，我希望在弹窗上「确认」本次告警，以便记录处理结果。
18. 作为客服人员，我希望在系统托盘看到客户端运行状态与当前词库来源（共享/本地缓存），以便知其健康。
19. 作为客服人员，我希望词库文件随客户端本地存在、离线也能监控，以便不依赖网络。
20. 作为客服人员，我希望告警不阻断我发送消息，以便沟通不被强行打断。

### 组长 / 主管
21. 作为组长，我希望按时间范围检索监控日志，以便复盘某时段内的违规情况。
22. 作为组长，我希望日志显示触发时间、目标软件、触发内容、处理结果，以便定位问题与责任。

24. 作为组长，我希望日志中的触发内容对违禁词高亮，以便快速审阅。

### 部署 / IT

### 通用 / 系统
31. 作为用户，我希望词库与日志的底层文件由程序管理，以便非技术人员无需手改文件。
32. 作为用户，我希望界面简洁实用、布局合理，以便上手成本低。
33. 作为客服人员，我希望同一违禁词在短时间内不反复弹窗，以便不被刷屏打扰。
34. 作为客服人员，我希望在弹窗「确认」后，该输入框不再就同一词重复告警，以便我安心修改内容。
35. 作为部署人员，我希望客户端首次运行有配置向导引导指定本地词库文件路径，以便快速上线。
36. 作为管理员，我希望能配置日志本地保留天数或一键清除日志，以便管理含客户内容的敏感数据。
37. 作为客服人员，当告警弹窗超时未确认时，我希望系统仍记录为「未确认」，以便组长复盘有据。
38. 作为用户，我希望客户端遇到较新版本词库时能兼容工作并提示，以便不会因为版本差异而停摆。
39. 作为客服/部署人员，当本机缺少所需的 .NET 运行环境时，我希望客户端启动即弹出提示并可直接打开官方安装地址，以便快速补齐环境，而不是默默崩溃或无响应。

## Implementation Decisions（实现决策）

### 模块划分
- **监控引擎（Monitoring Engine）**
  - UIA 监听器：按目标软件 EXE 名筛选前台/聚焦控件，订阅其 `TextChanged` 事件，读取成型文本。
  - 键盘钩子（辅助）：仅用于判断「当前是否在前台输入/活跃」，不还原中文文本。
  - 文本缓冲：暂存当前输入框文本供匹配。
  - Aho-Corasick 匹配器：词库编译为自动机，单次扫描返回全部命中。
- **本地词库（Local Word Library）**
  - 加载器：读取客户端本地（同目录/约定路径）的 `wordlib.json`。
  - 热重载：用 `FileSystemWatcher` 监听文件变更，自动重建内存自动机，无需重启。
  - 无网络依赖：词库文件已随客户端本地存在，离线可用。
- **告警模块（Alert Module）**：弹窗、声音、自有界面高亮，三项独立开关；弹窗含「确认」按钮。
- **审计日志（Audit Log）**：SQLite 写入与按时间范围检索。
- **配置（Config）**：目标软件 EXE 列表、告警开关、本地词库文件路径、去重窗口、留存天数。
- **词库编辑工具（Admin Tool）**：独立桌面程序（非服务），词库 CRUD + 导入导出 UI，导出 `wordlib.json` 供分发；不参与客户端运行时。

### 悬浮球状态指示器（Floating Orb）

悬浮球是**系统托盘之外的实时状态灯**，不与托盘互斥：托盘负责收起/退出/菜单，悬浮球负责"一眼可见的健康度"，二者并存。

- **三态语义**
  - **常态（蓝）**：监控引擎运行中，球体蓝色径向渐变 + 缓慢呼吸光。
  - **告警（红）**：检测到违禁词瞬间变红并显示扩散脉冲光环，**短促提示（默认 3 秒）后自动回到常态**；不持久闪烁，避免打扰客服。红光与弹窗/声音/高亮告警同步触发。
  - **异常 / 离线（灰黄）**：词库文件不可读、`FileSystemWatcher` 失效或引擎异常时变灰黄，提示需关注。
- **不打扰原则（硬性约束）**：球体小巧（默认右下角），可鼠标拖拽到任意位置，支持贴边自动隐藏与右键临时收起；红光必须短促衰减，禁止常亮/持续闪烁；悬浮球不参与文本捕获与告警判定，仅为状态可视化，零侵入。
- **交互**：单击球体展开迷你面板（今日告警数 / 启用词数 / 监控目标 / 当前词库来源）；双击恢复主窗口（可选）。
- **实现（C# / WinForms）**：无边框透明 `Form`（`FormBorderStyle = None`、`TopMost = true`、`Region` 裁成圆形、`Opacity`/`TransparencyKey` 实现半透明）；`Timer` 驱动呼吸/脉冲动画；`MouseDown/Move/Up` 实现拖拽；状态由监控引擎事件驱动切换。

### 运行环境检测与缺失提示（Runtime Bootstrap）

客户端启动时应检测本机是否具备所需运行环境（.NET Framework 4.8 / 对应运行时）。

- **检测时机**：程序入口最早阶段检测；缺失则**不进入主界面**，直接弹出引导对话框。
- **缺失提示对话框**：标题「需要安装运行环境」，正文说明缺少的运行环境名称与版本，并提供两个动作：
  - **「前往安装」按钮**：调用系统命令打开官方下载地址（如 `https://dotnet.microsoft.com/download/dotnet-framework/net48`），由用户自行安装；安装后重启客户端即可。
  - **「退出」按钮**：关闭程序。
- **设计原则**：不让用户面对「程序闪退 / 无响应」的困惑；把「缺环境」用一句话 + 一个按钮讲清楚，按钮直达官方安装页，无需用户自行搜索。
- **正常情况**：Windows 10 / 11 大多已预装 .NET Framework 4.8，此对话框通常不会出现，仅作兜底保护。若改为自包含（self-contained）发布，则此对话框不再需要。

### 关键架构决策（引用 ADR）
- **ADR 0001 分发**：本地 `wordlib.json` 文件分发为主（管理员导出后下发），客户端 `FileSystemWatcher` 热重载；SMB 自动拉取降为可选增强。
- **ADR 0002 匹配**：采用 Aho-Corasick 多模自动机，与词库规模无关的实时匹配。
- **ADR 0003 告警**：仅告警不拦截；高亮仅在本工具弹窗/日志内，不覆盖目标软件窗口。

### 关键行为细则（补充决策）

- **输入框判定**：仅监听属于目标软件（匹配 EXE 名）且处于前台聚焦的**可写文本控件**；控件类型白名单为 `Edit` 与 `Document`（含富文本编辑器的文档模式），忽略只读文本、按钮、ComboBox 等非编辑控件。
- **告警去重与冷却**：同一违禁词在同一输入框内，默认 **30 秒去重窗口**（可配置），窗口内不重复弹窗；客服在弹窗点击「确认」后，该输入框不再就同一词告警，直至文本变更清除该词或开启新会话。跨输入框的同词也遵循去重窗口，避免刷屏。
- **弹窗确认超时**：告警弹窗为非阻塞样式；若 **60 秒**内未点击「确认」，记 `disposition = 未确认（超时）` 并照常写日志。
- **词库 schema 兼容**：客户端遇到高于自身的 `schemaVersion` 时，忽略未知字段、按已知字段继续工作，并在状态栏提示「词库版本较新，部分功能可能受限」；不报错、不中断监控。
- **共享目录配置**：客户端首次运行启动**配置向导**填写共享目录 UNC 路径，存于本地配置文件，并提供「测试连接」按钮；之后可在设置中修改。

### 数据契约（来自对齐，精确表达优于散文）

**词库 JSON（共享目录权威文件）schema：**
```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-08-16T11:00:00+08:00",
  "words": [
    {
      "id": "uuid",
      "text": "违禁词示例",
      "category": "合规",
      "severity": "high",
      "enabled": true,
      "matchMode": "contains"
    }
  ]
}
```
> 客户端以 `updatedAt` 或内容哈希判定是否更新；`matchMode` 预留扩展（当前统一为 `contains`）。

**审计日志 SQLite 表 `AuditLog`：**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| triggered_at | TEXT | ISO8601 UTC 触发时间（"o" 格式，可字典序排序） |
| process_name | TEXT | 目标软件 EXE 名 |
| window_title | TEXT | 当时窗口标题 |
| matched_words | TEXT | 命中词 JSON 数组（含 id/text） |
| triggered_content | TEXT | 捕获到的文本或命中片段 |
| severity | INTEGER | 违禁词严重级别（0 低 / 1 中 / 2 高），供日志分级与仪表盘统计 |
| alert_channels | TEXT | 实际触发的告警通道（popup/sound/highlight） |
| disposition | TEXT | 处理结果：已弹窗/已响铃/已记日志/客服已确认/未确认（超时） |

### 部署
- 客户端与词库编辑工具均 .NET Framework 4.8 + WinForms。
- 客户端经 ClickOnce 发布（一键安装 + 自动更新），无服务器组件。
- 词库分发：管理员在编辑工具导出 `wordlib.json`，通过共享目录/U盘/邮件/GPO 等下发到各客户端本地路径；客户端监听文件变更自动热重载。

## Testing Decisions（测试决策）

### 测试边界（只测外部行为，不测实现细节）
- 匹配器：给定文本与词库，断言命中集合正确（含多命中、重叠、大小写/全半角边界）。这是最高层级 seam，且不依赖 UIA。
- 词库同步：模拟「共享可达」「共享不可达」「共享内容变更」三种情形，断言内存自动机与缓存正确切换（含离线降级）。
- 告警模块：以 mock UI 验证「开关组合 → 实际触发的通道集合」正确，且弹窗「确认」会写入 disposition。
- 日志检索：写入多日样例，断言按时间范围过滤与统计正确。

### 待测模块
- Aho-Corasick 匹配器（纯逻辑，优先单测）
- 词库加载/同步/缓存（可注入仿真文件系统）
- 告警通道开关与确认流
- 审计日志读写与检索

## Out of Scope（不在范围内）

- **拦截/阻止消息发送**：仅告警，不修改目标软件输入流（ADR 0003）。
- **覆盖层高亮目标软件窗口**：高亮仅限本工具界面（ADR 0003）。
- **中央日志聚合服务**：日志存于各客户端本地，不汇总到服务端。
- **跨平台 / 非 Windows**：仅 Windows 桌面。
- **联网 / 云功能**：完全离线。
- **运行时服务器 / 自动推送分发**：分发采用文件下发（管理员导出 `wordlib.json` 后分发），非服务端主动推送；仅在局域网可靠环境中可额外选配客户端定时从共享目录拉取（可选增强）。
- **多管理员并发编辑冲突解决**：单人管理词库，不处理并发合并。

## Further Notes（补充说明）

- **中文边界与误报缓解**：中文无词间空格，当前统一用子串 `contains` 匹配，存在误报（如「违禁」命中于「违禁品」）与漏报风险。本期缓解机制：① 默认按**短语/整词条**匹配，词库维护"整词口径"；② 弹窗与日志展示命中**前后文片段**，由客服/组长人工判定是否真违规；③ 后续可按词设置 `matchMode`（contains / exact-phrase）与"排除上下文"白名单。不过度工程，先落地 ① + ②。
- **UIA 附着稳定性**：目标软件控件随窗口开关而增毁，监听器需动态附着/脱离聚焦编辑控件，并容忍控件树变化。
- **日志留存与隐私（默认值）**：日志含「触发内容」明文，可能含客户 PII，属敏感数据。本期默认**本地保留 30 天**自动清理；日志文件限当前用户可读（目录 ACL）；提供"配置保留天数"与"一键清除"管理操作；加密不在 v1 范围，由部署方按合规要求决定。
- **跨终端日志汇总（v1 限制）**：本期日志保持**纯本地**，组长统计为**单机维度**；服务端不汇总各端日志。"多终端统一管理"在 v1 仅指**词库统一**，不含日志集中。集中汇总列为后续可选增强。
- **资源验收基线**：客户端闲置 CPU < 1%、内存 < 50MB；监控活跃峰值 CPU < 5%、内存 < 100MB。作为验收标准。
- **提权一致性**：默认客户端以标准用户运行，仅监控同权限目标进程；若目标软件以管理员运行，文档注明需以管理员身份启动客户端（不自动提权、不触发 UAC 弹窗打扰）。
- **分发与部署**：客户端安装源（ClickOnce）与词库文件分发彼此独立；词库 `wordlib.json` 经任意渠道下发到客户端本地路径，配置向导指定该路径。无服务器进程。
