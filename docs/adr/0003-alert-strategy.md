# ADR 0003 — 告警策略：仅告警不拦截，高亮限于自有界面

- 状态：已采纳
- 日期：2026-08-16

## 背景

需求要求"后台静默运行，仅在检测到违禁词时触发告警"，并列举弹窗、声音、高亮三种告警方式，同时要求"不打扰客服人员日常输入"。日志需记录"处理结果"。需明确：告警是否包含主动拦截消息发送；高亮作用在何处。

## 决策

1. **仅告警、不拦截**：系统检测到违禁词后只做提示与记录，不尝试阻止消息从客服软件发出。"处理结果"取值为 已弹窗 / 已响铃 / 已记日志 / 客服已确认。
2. **高亮限于自有界面**：高亮仅在**本工具的告警弹窗与日志列表**内把违禁词标红；不绘制覆盖层去标记或框住客服软件窗口。

## 取舍

- 优点：实现干净、稳定，完全满足"不打扰日常输入 / 非目标软件零干扰"；避免侵入式钩子带来的不稳定与误伤。
- 缺点：无法强制阻止违规内容发出（依赖客服自觉遵守）；高亮不直接出现在客服软件里，提示强度稍弱。
- 备选已排除：拦截发送（需更侵入的钩子，脆弱且易误伤正常输入）；覆盖层标记目标窗口（破坏"不打扰"承诺且脆弱）。

## 影响

- 告警模块 = 弹窗 + 声音 + 自有界面高亮，三项独立开关。
- 日志每条记录含 disposition 字段与告警通道明细。
- 不引入任何破坏目标软件输入流的钩子。
