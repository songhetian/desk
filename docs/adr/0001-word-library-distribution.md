# ADR 0001 — 词库分发：本地文件分发为主，自动拉取为可选增强

- 状态：已采纳（2026-08-16 修订；原"共享目录为主、本地缓存兜底"方案翻转）
- 日期：2026-08-16

## 背景

初版方案以 SMB 共享目录为唯一权威源，客户端定时轮询拉取 + 本地缓存兜底（离线降级）。复盘后认为：本工具定位是**本地、离线、无需联网**的桌面工具，不应依赖运行时服务器，也不应引入共享目录的权限配置、UNC 可达性、网络连通性等运维摩擦。更稳更简单的方式，是把词库作为随客户端本地的文件，由管理员导出后下发。

## 决策

- **词库权威文件 `wordlib.json` 随客户端本地存放**（同目录或约定路径），不再依赖运行时服务器。
- **管理员用独立的词库编辑工具（非服务）**维护词库（增删改查/导入导出），并导出该 `wordlib.json`。
- **文件分发**：管理员通过任意手段（可访问的共享目录、U 盘、邮件、组策略/GPO）把 `wordlib.json` 下发到各客户端本地路径。
- **客户端热重载**：用 `FileSystemWatcher` 监听本地文件变更，自动重建内存自动机，无需重启。
- **自动拉取（可选增强）**：仅在局域网可靠的环境中，客户端可额外定时从共享目录拉取词库；此为可选项，非必需。

## 取舍

- 优点：无运行时服务器、无共享权限/网络依赖；离线天然可用；部署极简；文件人类可读、易备份；更新方式灵活（任意渠道）。
- 缺点：更新依赖人工/脚本分发，非实时自动（取决于下发频率）；多终端一致性由各终端本地副本保证，需靠分发纪律。
- 备选已排除：原"客户端轮询 SMB 共享"为主（引入服务器/权限/离线复杂度，违背本地工具定位）；HTTP 拉取（需 Kestrel，略重）；服务端推送（需维护长连接、易丢）。

## 影响

- 取消运行时服务端；新增独立的**词库编辑工具**（桌面程序，非服务）。
- 客户端实现：本地文件加载 + `FileSystemWatcher` 热重载；UI 显示词库文件路径与最后加载时间，移除"共享/离线"二元状态（始终本地）。
- 管理端提供 CRUD + 导入导出，并明确"导出后如何分发"的操作指引（共享目录/U盘/邮件/GPO）。
- 部署说明改为：客户端 ClickOnce 安装（无服务器）+ 词库文件独立分发。
